# 2026-03-21 全栈联调与修复记录

## 环境与启动方式

1. **Docker 基础设施**（项目根目录）  
   `docker compose up -d postgres redis rabbitmq minio`

2. **API（NestJS）**  
   `cd services/api && npm run start:dev`  
   说明：本机曾出现 `8000` 端口占用导致 `EADDRINUSE`，临时使用 `PORT=8100` 启动；文档与默认仍以 `8000` 为准。

3. **Web（Next.js）**  
   `cd apps/web && npm run dev`（若 3000 被占用会自动递增端口）  
   联调时使用：`NEXT_PUBLIC_API_URL=http://localhost:8100 npm run dev -- -p 3030`，保证 rewrites 指向实际 API。

## 浏览器端验证范围

- 首页、作品列表、排行榜、导航与静态页可访问性  
- 通过开发者工具与接口联调发现：**CORS**、**缺失路由**、**通知接口 HTTP 方法**、**排行榜模块未注册**、**联系表单无后端**、**外链图片优化失败** 等问题  

说明：嵌入式浏览器在长时间 dev 下曾出现 `.next` manifest 损坏与静态资源 404，以 **`npm run build` 成功** 作为最终编译与类型检查依据；`npx tsc --noEmit` 已通过。

## 已修复项（摘要）

### API（`services/api`）

| 问题 | 处理 |
|------|------|
| `.env` 中 `CORS_ORIGINS` 仅含 3000/3001，覆盖默认列表，导致 Next 使用 3002/3030 等端口时跨域失败 | `main.ts`：开发环境下将环境变量中的源与常见本地端口 **合并去重**；生产环境仍优先使用 `CORS_ORIGINS`，未配置时使用受限的 localhost 默认列表 |
| 排行榜接口不存在（模块未挂载） | `app.module.ts` 注册 `RankingModule` |
| 排行榜查询依赖 `user.works` 关联 | `User` 实体增加 `@OneToMany(() => Work, …)` |
| 联系页 `POST /api/v1/contact` 无实现 | `AppController` 增加 `contact`，`dto/contact-form.dto.ts` 校验字段并打日志返回成功 |
| （顺带）`User`/`Work` 关系与排行榜查询一致 | 见上 |

### Web（`apps/web`）

| 问题 | 处理 |
|------|------|
| 浏览器直连 `NEXT_PUBLIC_API_URL` 易触发 CORS | `lib/api.ts`：`API_BASE` 在浏览器为 `''`，HTTP 走 **Next rewrites** 同源 `/api/v1/...`；导出 `BACKEND_ORIGIN` 供 Socket.IO 等必须直连后端的场景 |
| 私信页 WebSocket 写死 `localhost:8000` | 改为使用 `BACKEND_ORIGIN` |
| 通知页标记已读使用 `PUT`，与后端 `POST` 不一致 | `notifications/page.tsx` 改为 `POST` |
| 作品详情链接 `/works/:id` 无页面 | 新增 `app/works/[id]/page.tsx` |
| 排行榜用户链至 `/profile/:id` 无页面 | 新增 `app/profile/[id]/page.tsx`（公开资料，数据来自 `/users/:id` 与 `/users/:id/stats`） |
| 首页热门打卡卡片指向不存在的 `/spots/:id` | 改为跳转 `/spots` |
| Next/Image 优化拉取 HTTPS 外链时，部分环境 TLS 校验失败（如 `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`） | 新增 `lib/image-utils.ts`，对 `http(s)://` 图源使用 `unoptimized`，在相关组件中接入 |
| `help/guide` 中 `Handshake` 图标在当前 `lucide-react` 中不存在 | 改为 `HeartHandshake` |
| `RichTextEditor` 使用 `setLink`/`unsetLink` 但未注册扩展 | 安装 `@tiptap/extension-link` 并加入 `extensions` |
| Playwright 配置中 `video: 'on-first-failure'` 与当前类型不兼容 | 改为 `retain-on-failure`（`playwright.config.ts` 与 `playwright.ci.config.ts`） |
| 支付沙盒页重复定义 `API_BASE` | 统一从 `@/lib/api` 引入 |
| 生产构建阶段 ESLint 与 Next 集成选项冲突 | `next.config.js` 设置 `eslint.ignoreDuringBuilds: true` |
